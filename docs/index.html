01 / Principles

Safety is part of the architecture.

Every capability starts with a boundary, a receipt, and a way to fail closed.

01

Authority before action

A versioned policy profile decides which provider, model, command, network path, and executor may be used. Ambient credentials cannot silently widen that scope.

02

Effects stay separate

Discovering a Skill, MCP server, Hook, or Plugin only makes it eligible. Each read, process, command, and workspace effect still crosses its own gate.

03

Evidence over optimism

Sessions, plans, tool observations, verification, and recovery state are stored as durable evidence so a resumed run can explain what it knows—and what it does not.

02 / Architecture

A small core with explicit boundaries.

  1. A
    RequestUser intent and trusted configuration
  2. B
    PolicyResolve the maximum allowed authority
  3. C
    Agent loopPlan, inspect, act, and observe
  4. D
    Effect gatesApprove bounded tools and processes
  5. E
    EvidenceVerify, persist, recover, and report

Default posture

local-free-v1

  • Literal-loopback Ollama
  • No provider fallback
  • No automatic model pull
  • No ambient key activation

03 / Current build

Useful today. Deliberately unfinished.

BornAgent is an engineering and learning project, not a production-ready autonomous coding service. The public surface grows only when its safety contracts are testable.

Agent foundations

Streaming sessions, bounded tools, controlled edits, permissions, verification, and multi-provider contracts.

FOUNDATION

Durable work

Resumable sessions, goals, plans, continuous TUI state, and explicit completion evidence.

PHASE 16

Repository intelligence

Git-aware inventory, nested repository rules, indexed navigation, and freshness tracking.

PHASE 17

Capability platform

Local Skills, MCP primitives, declarative and separately approved command Hooks, plus immutable Plugin lifecycle and recovery.

PHASE 18

Task orchestration

Durable task graphs, deterministic single-Agent scheduling, bounded background recovery, worktree isolation, and explicit promotion.

PHASE 19

Controlled subagents

Authority-attenuated delegation, minimal child context, sealed local processes, bounded two-child scheduling, and verified structured receipts. M11 closure is still in progress.

04 / Quick start

Keep the first run local.

BornAgent requires Node.js 22.19+, pnpm 11.13.1, and optionally a local Ollama instance with qwen3:1.7b already installed.
